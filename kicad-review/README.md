# kicad-review（基板のレビュー）

KiCad 10 の基板（`.kicad_pcb`）を、ユーザーとコーディングエージェントがブラウザで一緒にレビューするローカルツール。KiCad の横に置いて使う。

エージェントが配線・レビューした後に残る項目（エージェントが変えたことの報告、人が KiCad で直した方が早い所、質問）を 1 件ずつ、

- 基板のどこか（その場所に印を付けて拡大する。ユーザーは KiCad で同じ場所を見る）
- どれだけ大事か（重要度）、誰が直すか（担当）
- エージェントとのやりとり（コメント）

と一緒に並べる。基板の上を押せば、その場所について新しく質問できる。

- Python 3.9+ の標準ライブラリだけ（サーバー）。ページは CDN を使わず、オフラインで動く
- KiCad 10（`kicad-cli` と KiCad 同梱の python）を別に入れておく
- 基板のプロジェクトのフォルダには書き込まない（基板を `cache/` にコピーしてから書き出す）
- サーバーは `127.0.0.1` で待ち受ける

## 起動

```
python kireview.py <board.kicad_pcb> [--data <フォルダ>] [--port 8199] [--no-open] [--kicad-bin "C:/Program Files/KiCad/10.0/bin"]
```

- `--data`: レビューと書き出しの置き場所（既定は今のフォルダ）。案件のデータなので、使う側の workspace のフォルダを渡す
- `--kicad-bin`: `kicad-cli.exe` と `python.exe` のあるフォルダ
- 起動すると既定のブラウザで `http://127.0.0.1:8199/` を開く（`--no-open` で開かない）。終了は Ctrl-C

## データの置き方

```
<data>/
  reviews/<基板名>.json        レビューの項目（git に入れてよい形の JSON）
  cache/<基板名>/<内容のハッシュ>/
    <基板名>.kicad_pcb          基板のコピー（ゾーンの塗りを除く）と .kicad_pro のコピー
    dump.json                  外形・銅箔層・部品・パッド（kireview_dump.py の出力）
    svg/<基板名>-<層>.svg       層ごとの絵
    meta.json
  figures/<基板名>/<名前>.svg   項目の説明の図（git に入れてよい）
```

- 書き出しは基板ファイルの内容のハッシュごと。今のものと 1 つ前を残し、それより古いものは消す
- `cache/` は消しても、次の起動で作り直す

## 書き出し

1. 基板と `.kicad_pro` を `cache/` にコピーする。ゾーンの塗り（`filled_polygon`）は除く（配線・パッド・ビアが読みやすいため）
2. KiCad 同梱の python で `kireview_dump.py` を実行し、外形（Edge.Cuts）の範囲、銅箔層（重ね順）、部品（番号・値・面・位置・範囲）、パッド（番号・ネット・位置・大きさ・層・形）を `dump.json` に書く
3. `kicad-cli pcb export svg --mode-multi --page-size-mode 1 --exclude-drawing-sheet --drill-shape-opt 2` で、全銅箔層と F.Silkscreen・B.Silkscreen・Edge.Cuts を 1 層 1 枚の SVG にする。色は KiCad の基板エディタの配色（`--theme` を渡さない）。背景は透明
4. 各 SVG のページを、基板の外形の周り 2 mm に切り詰める

座標: `--page-size-mode 1` の SVG は viewBox の単位が mm で、原点が基板の座標の原点と同じ（KiCad 10 で確認。`width` の mm と viewBox の幅の比を毎回読んで換算する）。切り詰めた後も viewBox は基板の mm のままなので、画面では「画面の px = 基板の mm × 倍率 + ずらし」の 1 つの変換を全部の層の絵と印に使う。

基板ファイルの更新日時を 2 秒ごとに見て、変わったら（KiCad で保存したら）裏で書き出し直す。その間は前の絵を出し、ページの上端に「再読み込み中」と出る。書き出しに失敗したときは前の絵のまま「書き出し失敗」と出す（マウスを乗せると理由）。

## 画面

- 左上: 項目の一覧。重要度（必須 → 推奨 → 任意 → 情報）ごとに、状態の印、番号、重要度、担当、題名。「OK」「修正済み」の項目は「完了も表示」を押したときだけ出る（修正済みは薄い緑の行に取り消し線）。「残り x / 全 y　✔ 修正済み n」。エージェントの新しい返信には「返信」の印
- 左下: 選んだ項目の詳細。重要度とその意味、担当、場所（面と座標）、部品、依頼（題名の下に強調）、理想、経緯、やりとり。下端に固定の欄（状態のボタン ✔ 修正済み / ⚑ 直して / ✓ OK と、1 行のコメント欄。内容が長くても見ながら押せる。ボタンはもう一度押すと未確認に戻る。質問や直し方の希望はコメントに書いて送る（送るとエージェントの番になる）。コメントは書くと伸び、Ctrl+Enter で送信）。一覧と詳細の境目は上下にドラッグできる（ブラウザに記憶）
- **⚑ 直して**: エージェントに直してもらう（状態は `修正を依頼`。エージェントの番になる）。シルクの位置など、人が手でやるまでもない修正に使う。コメントは任意（書いてから押すと一緒に送る）
- **✓ OK**: 確認した・このままでよい（直さない）。情報の項目を見た時も、指摘を受け入れて直さない時もこれ（状態の値は `このまま`）。理由を残したい時はコメントに書いてから押す
- 次の項目へ: 状態のボタンを押すと、一覧の次の行を選ぶ（手で戻らなくてよい）。コメント欄に書いてから押すと、状態とコメントを一緒に送る。コメントを送っても次の行へ。**↑ / ↓** で一覧を 1 行ずつ移る（コメント欄などに入力中は効かない）
- 右: 基板。背景は黒、層の絵を KiCad の色で重ねる。裏も反転せず、KiCad のエディタと同じく表から見た向きで出す
  - 表示: `表`（F.Cu・F.Silkscreen・Edge.Cuts）、`裏`（B.Cu・B.Silkscreen・Edge.Cuts）、`内層`（内層の銅箔・薄くした F.Silkscreen・Edge.Cuts）、`全部`。層ごとのチェックでも切り替えられる。選んでいる面の層を一番上に重ねる。表示の選択はブラウザに記憶
  - `ピン・ネット`: 表示している面（一番上の銅箔層）のパッドに、ピンの番号とネットの名前を KiCad のように出す。パッドが画面で小さいうちは出ず、拡大すると番号、さらに拡大するとネットの名前も出る（配線のネットの名前は出ない）。選択はブラウザに記憶
  - ホイールでカーソルの周りを拡大、ドラッグで移動、`全体` で基板全体（もう一度押すと元の拡大に戻る。全体を見て詳細へ戻る用）
  - 項目の印: 輪（`r`）か四角（`w`・`h`）と番号。色は状態で、未確認は黄、質問は紫、修正済みは緑で中を薄く塗り番号に ✔、OK（このまま）は細い灰色（古い状態の自分で修正・修正を依頼は橙）。表示している銅箔層に無い項目は破線
  - 項目を選ぶ（一覧か印を押す）と、その項目の面の表示に切り替え（`pins` があれば最初のピンの面。表面実装のパッドは片面だけなので。無ければ `sides` の先頭）、項目を中心に周り約 20 mm が見える倍率にする。ほかの印は薄くなる。Esc で選択を解除
  - 印の無い所を押すと、近くのパッド（「C4 1 +BATT_4V」、1.5 mm 以内）か部品（「U1 (LGS4056H) 裏」）を出し、`ここに質問` から 1 行の質問を送れる。送ると新しい項目（`Q1`, `Q2`, …）になる
- ページは 3 秒ごとにレビューと基板の版を読み直す（選択・一覧の位置・拡大はそのまま）

## レビューのファイル（`reviews/<基板名>.json`）

```json
{"board": "<基板ファイルのパス>", "rev": 12, "items": {"B3": {...}, "Q1": {...}}}
```

| 欄 | 内容 |
|---|---|
| `title` | 1 行の題名 |
| `severity` | `必須`（直さないと動かない・壊れる・製造で不良）/ `推奨`（直した方がよい：性能・信頼性）/ `任意`（できれば）/ `情報`（そのままでよい・変更の報告） |
| `owner` | `人`（KiCad で手で直す方が早い）/ `エージェント` / `未定` |
| `sides` | 面のリスト（`"F"`, `"B"`, `"In1"`, `"In2"`, …）。先頭の面で表示する |
| `x`, `y` | 場所（基板の mm。KiCad の座標と同じ） |
| `r` または `w`, `h` | 輪の半径（mm）、または四角の幅と高さ（mm）。どちらも無ければ `r` = 1 |
| `refs` | 関わる部品・パッド（例 `["U1"]`、`["C4.1"]`）。確かめる用で、探す役には立たないので、場所はピンで示す |
| `pins` | 項目が指すピン（例 `["U3.2", "C12.2"]`）。項目を選ぶと、図でそのパッドを囲み、部品の外側から矢印を向け、ピンが入る倍率まで寄せる。無ければ `refs` のうち `部品.番号` の形のもの。範囲（`r`・`w`/`h`）より先に、ピンが分かる項目はピンを入れる。配線を頼む項目は配線 1 本ごとに分け、IC・モジュールの側の 1 ピンだけ（相手は KiCad のラッツネストで分かる） |
| `ask` | 依頼：ユーザーにしてほしいことを、頼む形で端的に（「〜をつないでください」）。やり方の案も、短くここに。エージェントが直すものは「対応は不要です。こちらで直します」。詳細の題名のすぐ下に強調して出る |
| `signal` | 配線を頼む項目だけ：信号の種類（PWM の周波数、アナログ、I2C、ほぼ一定の論理など）、流れる電流の目安（線の幅を決める用）、引くときの注意（並走させない線など） |
| `ideal` | 理想：どうなっていればよいか（1 文） |
| `figures` | 説明の図のファイル名のリスト（`<data>/figures/<基板名>/` に置く svg・png・webp・jpg）。依頼のすぐ下に出て、押すと全画面（もう一度押すか Esc で戻る）。寸法の関係など、文だけでは状況が想像しにくい項目に付ける |
| `background` | 経緯：なぜそうなったか（道具の都合、試したこと）。補足なので後ろに出る |
| `text`, `action` | 古い形（内容・直し方）。`ask` を使う項目では空にする |
| `status` | `未確認` / `修正済み` / `修正を依頼`（⚑ 直して。エージェントの番）/ `このまま`（✓ OK: 確認した・直さない）/ `質問`（基板を押して作った項目。古いレビューも）。ページのボタンは 修正済み・直して・OK の 3 つ。古い `自分で修正` も読めて表示する |
| `thread` | `[{"who": "user" \| "agent", "text": "…", "time": "YYYY-MM-DD HH:MM:SS"}]` |
| `near` | 基板を押して作った項目だけ: 押した所のパッドか部品（「C4 1 +BATT_4V」） |
| `status_rev`, `agent_rev` | サーバーが付ける。ユーザーが状態を変えた版と、エージェントが最後に答えた版（返信待ちの判定に使う） |

基板を押して作った項目（`Q1` …）は、重要度 `情報`、担当 `未定`、状態 `質問` で、押した点を `x`・`y`、近いパッドか部品を `refs` に入れる。

## API（`http://127.0.0.1:8199`）

本文は UTF-8 の JSON。

- `GET /api/review`: 基板のパス、レビューのファイル、`rev`、全項目（`items` は id → 項目）
- `GET /api/review/pending`: エージェントの番の項目（最後の発言がユーザー、または `修正を依頼`・`質問` にした後にエージェントが答えていない）。`items` は `id` 付きのリスト
- `POST /api/review/item` `{"id": "B3", "title": "…", "severity": "推奨", "owner": "人", "sides": ["B"], "x": 99.0, "y": 117.8, "r": 1.5, "refs": ["U1"], "text": "…", "action": "…"}`: 項目の作成・置き換え。`status` と `thread` は渡さなければ今のものを残す（新しい項目は `未確認`）
- `DELETE /api/review/item?id=B3`: 項目の削除
- `POST /api/review/agent` `{"id": "B3", "reply": "…", "status": "修正済み"}`: エージェントの返信・状態の変更（どちらか一方でもよい）
- `POST /api/review/user` `{"id": "B3", "status": "このまま", "comment": "…"}`: ページが使う（ユーザーの状態の変更・コメント）
- `POST /api/review/new` `{"x": 98.2, "y": 113.25, "side": "B", "comment": "…"}`: ページが使う（基板の点についての質問。`refs` はサーバーが dump から埋める: 1.5 mm 以内のその面のパッド、無ければ点を含む部品）
- `GET /api/board`: 基板のパス、版（`version` = 内容のハッシュ）、状態（`ok` / `reloading` / `error`）、外形の範囲 `bbox`、絵の範囲 `crop`、銅箔層、層の絵の URL（`/svg/<版>/<ファイル>`）、`dump`
- `GET /api/board/version`: 版と状態だけ（ページの見張り用）
- `POST /api/reload`: 基板ファイルを今すぐ見直す（内容が同じなら書き出しはそのまま）

Windows で日本語を送るときは、本文を UTF-8 の JSON ファイルにして `curl --data-binary @item.json -H "Content-Type: application/json" http://127.0.0.1:8199/api/review/item` で送る（コマンドラインに直接書くと文字化けすることがある）。

## エージェントの進め方

1. 項目を `POST /api/review/item` で登録し、`kireview.py` を起動する（起動後の登録もページに 3 秒以内で出る）
2. 続けて `python kireview_wait.py --port 8199` をバックグラウンドで実行しておく（Claude Code なら Bash の `run_in_background`）。エージェントの番の項目があると、その内容（id、状態、場所、ユーザーのコメント）を表示して終了し、その終了でエージェントが起きる
3. エージェントは `POST /api/review/agent` で返信する（直したら `"status": "修正済み"`）。もう一度 `kireview_wait.py` を起動する
4. 起動時にすでにエージェントの番の項目があれば、すぐに表示して終了する（待っていない間のコメントも落とさない）

ユーザーが KiCad で直して保存すると、ページの絵は自動で新しくなる。

## ファイル

| ファイル | 役目 |
|---|---|
| `kireview.py` | 入口（HTTP サーバーとページの配信） |
| `kireview_board.py` | 書き出し（コピー・塗りの除去・SVG・dump）、ファイルの見張り、近いパッドの検索、レビューの項目、API（`Api` クラス。別のサーバーに組み込める） |
| `kireview_dump.py` | KiCad 同梱の python で実行し、`pcbnew` で基板のコピーを読んで JSON を書く |
| `kireview_wait.py` | エージェント用の待ち受け |
| `index.html` | ページ |

## 制限

- 塗りを除いて書き出すので、ゾーン（ベタ）は絵に出ない
- 層の絵は書き出し時の配色。KiCad の配色を変えたら、基板を保存し直すか `cache/` を消して書き出し直す
- 拡大の上限は 150 px/mm
- 近いパッドの検索は銅箔のパッドだけ（ビア・配線は対象外）
- 書き出し中に基板が読めない（保存の途中など）と「書き出し失敗」になり、次に基板が変わったときに書き出し直す
